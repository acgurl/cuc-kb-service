## 发现与 tradeoff

1. **展开真实有效**：split_adjacent 5/6 @5，12 个证据项中 5 个经展开合并命中（w23/w25/w26/w27/w28 均为「anchor+exp」单命中覆盖双项，3 题直接 @1 命中）。唯一 miss w24 的两块排在 rank 8——展开只增文本不改排序，救不了排序丢失，与 HANDOFF 已知边界一致。
2. **版本降权 6/6 检索命中，但 w33 旧版仍压 top1**：5 题新版 top1、旧版 rank 2-4 或不在候选；w33（困难认定复核）旧版 2019-77 rerank 分差大于 0.05，降权翻不动，新版 rank 2 仍在 top5 故检索计命中，**但 LLM 先读旧版答「固定 4-5 月」被判编造**——这是本轮唯一「检索命中≠端到端正确」的版本案例，说明 0.05 的软降权对分差大的对不够。
3. **cross_clause 仍最弱 6/10**：w01/w02 证据散落 rank 4-10（ranking/fusion_pool），w03 @10 才齐；与 v1 结论一致，候选多样性（item4）仍是方向。注意 w01 top1 是 **2017 版研究生学籍规定**（不在 12 对替代关系内），LLM 靠旧版同文条款答对（correct=1）——事实对但出处旧，属版本族/替代关系覆盖缺口。
4. **表格块召回缺口**：w10（文学艺术 ≥16 表）recall 阶段双路均无、w21（工学 ≥14 表）同；w20 深圳表 fusion_pool 丢失。纯数字表格块 dense/BM25 召回弱，与 v1 c50 图书馆时间表同类，属 ingest 侧 embed_text 增强问题。
5. **误拒清零、误接受 1**：v2 无 false_refuse（v1 上线后仍有 ev09/ev10）；w35 校园卡补办时长属属性级误接受（conf 0.949，answerability guard 不覆盖「时长」属性），同类 v1 有 3 个。
6. **LLM 端到端 30/34 correct（88%）、fabricated 2**：非 correct 四题 = w10/w20（证据召回缺失→诚实拒答，其中 w20 叠加 judge JSON 解析失败噪声，parse_verdict 记 correct=0）、w32（检索 top1 正确但 LLM 臆造「2025-2 也有相同告知程序」）、w33（旧版 top1 带偏）。w32 提示：即使检索正确，agent 层也应在引用中标注 superseded 关系防新旧等同臆造。
7. **延迟 P50 2138/P95 3603ms** 高于 v1 同日 1209/1867：v1 复跑命中查询向量 LRU 缓存，v2 全为新查询每次含 embed 北京往返；属冷缓存口径差异，非性能退化。

## 局限与后续

- 本轮**零代码零配置改动**，纯评测；线上排序逻辑未动，v2 heldout 回归基线不受影响。
